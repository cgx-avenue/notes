## 什么是cursor
简单说，基于vscode二次开发的使用LLM对programming特殊设计的IDE。里面的各种features，无论是chat+agent，或者是cursor_rules, codebase,symbol command等等，都是为了引入合适的上下文，方便我们更好的掌控这个工具。

### Cursor的优势
1. 和IDE的无缝集成，暂时来看比vscode+extension的方式要好用。操作的细节更多，能力也更强。
2. 使用最擅长编程的Claude sonnet模型。
3. 暂时来看各种工具设计的比较合理，工作流也能顺利自己定制。
4. 各种大模型都有集成，可以任选。

### Cursor的劣势
1. 贵。按年付费每个月也要100多。
2. 模型调用和直接使用模型token等消耗不一致，有更多的overhead。

# Prompt提示词框架 
我认为prompt符合二八法则：
1. 有一定格式肯定比没有好
2. 20%精力的prompt就已经实现80%功能了，剩下的20%功能的fine-tuning，需要花费80%的精力才可以。是否如此需要具体问题具体分析。

## CO-STAR框架
由新加坡政府技术局（GovTech）的数据科学与 AI 团队开发，重点在于确保提供给 LLM 的提示词是全面且结构良好的，从而生成更相关和准确的回答。

CO-STAR 框架可以拆解为六个维度：

1. **Context (C)**：设定背景。提供与任务相关的背景信息，帮助 LLM 理解具体的情境，从而确保其响应与给定情况相关。例如，撰写一篇关于环境保护的文章，需要提供当前的环境问题、相关的数据和案例等背景信息[1](https://juejin.cn/post/7399984522106650651)。
    
2. **Output or Objective (O)**：明确任务目标。这部分指定了希望 LLM 完成的任务，指导 LLM 生成符合预期结果的响应。例如，目标可能是撰写一篇介绍环境保护措施的文章，或是分析一项环境政策的影响[1](https://juejin.cn/post/7399984522106650651)。
    
3. **Specificity or Style (S)**：具体或风格。提供有关所需回答的更多细节，避免有歧义，同时也避免 LLM 泛化的回答内容。风格可能包括正式、非正式、技术性或对话性的风格，具体取决于背景和预期的读者[1](https://juejin.cn/post/7399984522106650651)。
    
4. **Task or Tone (T)**：任务或语气。提供给 LLM 具体的任务和执行方案，比如分析、总结、翻译或者写作等。设定回答的语气，可以是专业的、友好的、严肃的等，适合目标受众和情境[1](https://juejin.cn/post/7399984522106650651)。
    
5. **Assumptions or Audience (A)**：假设或受众。帮助 LLM 补充未明确说明的内容，比如对于目标内容的假设。提供给 LLM 关于目标受众的知识水平，让 LLM 选择适合于目标受众的语言和词汇、参考资料和风格等[1](https://juejin.cn/post/7399984522106650651)。
    
6. **Requirements or Response (R)**：回答必须包含的要素。列举出回答内容的约束条件，比如长度限制、结构限制等，可以包括回答应采用的结构或模板[1](https://juejin.cn/post/7399984522106650651)。





## RTGO框架

### 四层递进结构
* Role（角色）：定义AI的专业身份
	资深Python开发工程师 / 十年经验的数据分析师
* Task（任务）：明确具体操作指令
	分析2025年Q1用户行为数据 / 编写智能家居系统API文档
* Goal（目标）：设定可量化目标
	生成包含3个关键趋势的可视化报告 / 输出符合OpenAPI 3.0规范的文档
* Objective（操作要求）：细化格式规范
	使用Markdown表格呈现，附带Matplotlib代码示例
