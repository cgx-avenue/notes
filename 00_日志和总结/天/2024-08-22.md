# docker-compose 和 docker compose的区别
在docker实际使用中，经常会搭配Compose，用来定义和运行多个 Docker 容器。使用时会发现，有时候的指令是docker-compose，有时候是docker compose，下面给出解释。

docker官方文档：https://docs.docker.com/compose/install/linux/

官方文档中其实已经给出了答案：Compose分为V1和V2版本，安装方式分为两种，一种是独立安装，一种是插件安装，所以如下有四种组合方式：

|   |   |   |
|---|---|---|
||V1|V2|
|standalone（独立式安装）|docker-compose|docker-compose|
|plugin（插件式安装）|没有安装成功|docker compose|

注：V1版本的Compose，按照插件手动安装的方式安装后报错，个人认为V1版本的Compose是不支持插件式安装的。

### 结论：

1、独立安装的Compose，不论是V1还是V2版本，指令都是docker-compose（中间是短横线）

2、插件安装的Compose，在V2版本，指令是docker compose（中间是空格），最新版的docker安装时会自动以插件的形式安装docker compose

3、支持同时采用两种方式安装Compose，安装后可以同时使用docker-compose和docker compose


# streamlit 加载markdown和图片
问题描述：
我有一个根目录，包含十几个子目录，根目录和每个子目录下均有一个readme.md文件，同时每个md文件中有加载图片，且对应的图片均在各自目录的resources文件夹下。如果直接使用st.markdown，图片无法显示。
解决方案：
[在基于streamlit的程序中使用 Markdown 和图片_streamlit markdown-CSDN博客](https://blog.csdn.net/xbsysy/article/details/140027291)

基于这个，我做了一些修改，主要是添加了path
```python
import streamlit as st

import re

import os

  
  

def render_markdown_with_images(markdown_text,path):

    # 匹配 Markdown 图片语法 ![alt text](image_url)

    pattern = re.compile(r'!\[.*?\]\((.*?)\)')

  

    # 记录上一个位置

    last_pos = 0

  

    # 查找所有匹配项

    for match in pattern.finditer(markdown_text):

        # 显示上一个位置到匹配位置之间的文本

        st.markdown(markdown_text[last_pos:match.start()], unsafe_allow_html=True)

  

        # 显示图片

        img_url = match.group(1)

        st.image(path+"/"+img_url)

        # st.image(img_url)

  

        # 更新上一个位置

        last_pos = match.end()

  

    # 显示剩余的文本

    st.markdown(markdown_text[last_pos:], unsafe_allow_html=True)

  

def add_readme_as_markdown(path):

    with open(path+ "/README.md", "r", encoding="utf-8") as md_file:

        temp = md_file.read()

        render_markdown_with_images(temp,path)
```
调用的时候直接这样：
```python
with st.container(height=500):

    utils.add_readme_as_markdown(os.path.dirname(__file__))
```
